# LisiOS — сборка ISO

Этот проект собирает загрузочный образ **LisiOS** (Arch Linux + Hyprland + собственная оболочка на Quickshell + графический установщик).
Windows и ваши диски при сборке не затрагиваются: всё происходит в контейнере или на серверах GitHub.

## Сборка через GitHub: пошагово

Всё делается в браузере, ничего ставить на компьютер не нужно.

1. Откройте **github.com** и войдите (или нажмите *Sign up* и зарегистрируйтесь).
2. Справа вверху нажмите **+ → New repository**. Имя: `lisios`. Выберите **Private**. Нажмите **Create repository**.
3. Распакуйте этот архив на компьютере. В распакованной папке должны быть `README.md`, `build.sh`, папки `profile`, `scripts`, `assets` и **скрытая папка `.github`**.
   (Если не видно `.github`: в Проводнике *Вид → Показать → Скрытые элементы*.)
4. На странице нового репозитория нажмите **uploading an existing file**. Перетащите в окно **всё содержимое папки** (файлы и папки, не саму внешнюю папку), дождитесь загрузки и внизу нажмите **Commit changes**.
   В репозитории должно быть 56 файлов; загрузка через браузер разрешает до 100 файлов за раз.
5. Проверьте, что файл **`.github/workflows/build-iso.yml`** появился в репозитории. Если его нет (скрытая папка не загрузилась): нажмите **Add file → Create new file**, в поле имени введите `.github/workflows/build-iso.yml`, вставьте содержимое файла `ЗАПАСНАЯ-КОПИЯ-build-iso.yml.txt` и нажмите **Commit changes**.
6. Откройте вкладку **Actions**. Сборка **Build ISO** запускается сама после загрузки. Если не запустилась: слева выберите **Build LisiOS ISO** → справа **Run workflow** → зелёная кнопка **Run workflow**.
7. Подождите 20–40 минут (жёлтый кружок → зелёная галочка). Откройте запуск, внизу в разделе **Artifacts** скачайте **lisios-iso** (ZIP с `.iso`).
8. Если красный крестик: откройте запуск и скачайте **build-log** из Artifacts (или откройте шаг *Build ISO inside Arch Linux container*) и пришлите мне последние ~50 строк лога.

## Сборка у себя

* **Linux / macOS / Windows с Docker Desktop:** `./build.sh` (Windows: `powershell -ExecutionPolicy Bypass -File build-windows.ps1`).
  Docker Desktop на Windows использует WSL2, поэтому при зависшем WSL выбирайте GitHub Actions.
* ISO появится в папке `out/`.

## Свой логотип и обои

* Положите логотип в **`assets/logo/logo.png`** (PNG с прозрачным фоном, от 512×512). Без него сборка использует серую заглушку `logo.placeholder.png` и предупредит об этом. Логотип используется в загрузочной анимации (Plymouth), сплэше оболочки, панелях и установщике.
* Обои: `assets/wallpapers/default.png`. После установки обои и загрузочный логотип меняются в *Системных настройках* без пересборки.
* Текст лицензии для установщика: `profile/airootfs/usr/share/lisios/LICENSE.txt` (сейчас там заглушка — замените своим).

## Проверка в виртуальной машине (обязательно до установки на реальный диск)

* **Windows:** VMware Workstation Player или VirtualBox. Включите *3D-ускорение*, 4 ГБ RAM, 2+ ядра, диск 40 ГБ (виртуальный файл), в настройках ISO подключите как CD/DVD. Или QEMU: `scripts\test-vm.ps1 -Iso путь\к\lisios.iso`.
* **Linux:** `scripts/test-vm.sh out/lisios-*.iso` (QEMU с virtio-gpu и 3D).
* Оболочка (Hyprland) требует OpenGL. В ВМ без 3D-ускорения графическая сессия может не запуститься — тогда откроется консоль, а систему можно установить командой `sudo lisios-install-cli --help`.
* Установщик в live-режиме стирает **только выбранный диск**. В виртуальной машине это виртуальный диск, Windows не затрагивается. Не выбирайте физический диск, пока не убедитесь, что всё работает в ВМ.

## Что внутри

```
build.sh, build-windows.ps1      запуск сборки (Docker)
.github/workflows/build-iso.yml  сборка на GitHub
scripts/build-in-container.sh    вся логика сборки: берёт профиль releng, накладывает LisiOS, запускает mkarchiso
packages.required / .optional    списки пакетов (отсутствие обязательного пакета останавливает сборку с понятной ошибкой)
profile/airootfs/                файлы, попадающие в систему
  etc/skel/.config/hypr/         конфигурация Hyprland (анимации, скругления, горячие клавиши)
  usr/share/lisios/shell/        оболочка (QML): обои, верхняя панель, док, меню Lisi AI, уведомления, центр управления, сплэш
  usr/share/plymouth/themes/     загрузочная анимация установленной системы
  usr/lib/lisios/installer/      установщик: backend.py (разметка, копирование, загрузчик) и gui.py (экраны)
  usr/lib/lisios/settings/       «Системные настройки»: язык, скорость анимаций, обои, загрузочный логотип
assets/                          логотип и обои
```

## Как устроено

* **Live-образ** запускается в сессию Hyprland → оболочка → сплэш (чёрный экран, логотип появляется и улетает вверх) → окно установщика.
* **Установщик:** приветствие и язык → лицензия → диск → пользователь → драйверы → установка → завершение. Кнопка «Перейти на рабочий стол» проигрывает анимацию и перезагружает компьютер в установленную систему.
* **Безопасность диска:** принимается только диск из списка; диск с установочным носителем и диски со смонтированными разделами недоступны; нужна отдельная галочка подтверждения стирания, для дисков с Windows показывается предупреждение; запись EFI-загрузчика идёт только в ESP выбранного диска (`--removable`), чужие записи не меняются.
* **Драйверы:** Wi-Fi, Bluetooth, микрокод, графика Mesa/Intel и звук ставятся всегда (они уже в образе) и проверяются после установки по базе пакетов. NVIDIA — по выбору: по модели видеокарты определяется, подходит ли `nvidia-open` (Turing и новее); для старых карт остаётся открытый драйвер nouveau. Для NVIDIA, печати и кодеков нужен интернет.
* **Анимации:** скорость меняется в настройках (0.5×–3×) и применяется сразу.
* **Lisi AI:** кнопка на нижней панели открывает меню; поле запроса готово, но API не подключён — провайдер и формат запросов не определены. Ключи и адреса не придуманы.

## Что НЕ проверено (честный статус)

Проект написан без возможности собрать ISO и загрузить его: в среде, где он создавался, не было Docker-демона и доступа к репозиториям Arch. Проверено: синтаксис bash-скриптов, компиляция Python-кода, сухой прогон установщика (`dry_run`: порядок команд и параметры), патчинг `profiledef.sh`. **Не проверено:** сам `mkarchiso`, загрузка ISO, QML оболочки (API Quickshell), PyQt-интерфейс установщика, GRUB, Plymouth, NVIDIA. Первый запуск почти наверняка потребует 1–3 итераций исправлений по логу.

Известные ограничения первой версии:

* Три кнопки окна (красная/жёлтая/зелёная) показываются в верхней панели для активного окна. Кнопки прямо на заголовке каждого окна — следующий этап (плагин hyprbars или собственный композитор).
* Окна открываются плавающими (перемещение и изменение размера мышью, `SUPER`+перетаскивание).
* Lisi AI не подключён к API; нет системы обновлений; поддерживается только x86_64.
* После установки вход — автоматический (можно отключить на экране «Пользователь»).
* Секретная загрузка (Secure Boot) не настроена: отключите её в UEFI.

## Изменения в этой версии (первый проход)

* Wine добавлен в обязательные пакеты и проверку обязательных компонентов.
* В установщике добавлен переключатель Steam runtime-библиотек. Клиент Steam не устанавливается; для 32-битных библиотек включается репозиторий multilib внутри целевой системы.
* На шаге выбора диска добавлена кнопка «Пропустить установку на диск»: она закрывает мастер, оставляя live-сессию работать с USB, и не вызывает backend форматирования.
* Оранжевые акценты добавлены в установщик и нижнюю панель; заставка дополняется надписью LisiOS.
* Из предоставленного референса подготовлен прозрачный логотип `assets/logo/logo.png` без водяного знака.

**Ограничения, которые намеренно не реализованы без уточнения:** отдельный первый диск для временных/системных файлов (неясно, должен ли это быть кэш или постоянная часть ОС); ручная разметка с сохранением Windows; полноценный экран входа (сейчас поведение автовхода остаётся настраиваемым). По умолчанию текущий установщик всё ещё полностью очищает только один явно выбранный целевой диск после отдельного подтверждения.

**Проверка:** Python-файлы проходят `py_compile`. Сборка ISO и запуск GUI/Quickshell в этой среде не выполнялись; перед использованием обязательна проверка в виртуальной машине с отдельным виртуальным диском.
